# 命中绶带 · 已确认规则与近战接口研究

更新：2026-10-11。本文记录已确认的显示规则和接口研究；不是已安装功能的说明。当前图标为v14，保留v11确认的8项即时命中图标，H01总命中仅为累计绶带。v14按v13意见将击穿改用旧完全击穿图、让新完全击穿的整颗弹头穿过方框、放大部位摧毁的关节准星；统计含义保持。离线状态原型、逐项入口及异常状态施加计数的缺口见[本轮接入研究](hit-interface-research-2026-10-11.md)。

## 已确认规则

- 战斗时在右侧显示命中结果小图标；任何情况下同类只有一个图标，新的同类命中只增加数字。
- 总命中不显示即时小图标，只在打开地图后的累计绶带区占一个位置；仍单独计总数，不把可重叠的分类相加。
- 最后一次已纳入统计的命中后，连续 2 秒没有新命中，收起这一批小图标。新命中刷新收纳时间。
- 打开地图后，在右上角战争绶带区域显示本场累计的命中绶带；悬停查看各类命中数量。收起小图标不清空本场累计，同类绶带不重复占位。
- 关闭地图后收回累计绶带区域。沿用已有 F8 开关、原生 HUD 自适应及完整任务列表让位的目标；隐藏只影响显示。
- 范围为本人弹体的直接命中，包括子弹、霰弹丸、火箭及炮弹。近战命中同步研究，接口可靠后纳入，不细分枪托、刺刀和专用近战武器。
- 喷火喷流本轮排除，预期不算命中；持续燃烧、地面火焰和爆炸范围伤害不增加命中数。燃烧枪械的实际弹丸直接命中仍属于弹体命中。

普通射击命中采用游戏记录的弹体命中口径，不把开火一次、命中一颗霰弹丸、造成一次伤害或一次击杀混为同一单位。

## 现有能力

| 记录 | 已知接口或数据 | 验证边界 |
| --- | --- | --- |
| 本人弹体命中增长、累计及武器来源 | `projectiles_hit`，`0x897A5551`；Runtime `player_hit` | 来源累计不含逐次目标、部位、穿甲倍率或反弹结果。本项目尚未接入新的命中显示。 |
| 来源伤害量 | `dealt_damage`，`0x5C7A2930` | 包含原生归属到该来源的爆炸和状态伤害；不能换算为命中次数。 |
| 近战击杀 | `dealt_melee_kills`，`0xC7680A1B` | 已用于本项目近战杀敌绶带；只证明击杀记录，不证明未致死的近战命中记录。 |
| 专用近战武器的伤害定义 | SDK 的 `MeleeWeaponComponentData.DamageInfoType`，以及支持武器的 `runtimeAttacks.kind = Melee` | 静态定义可辨识近战攻击分支；不是运行时命中通知。只筛选专用近战武器哈希，不能证明已覆盖枪托、刺刀等动作。 |

接口依据：[Runtime 命中与伤害说明](https://github.com/SkyeShade/HD2Runtime/blob/master/docs/events.md#damage-and-hit-attribution)、[武器攻击分支说明](https://github.com/SkyeShade/HD2Runtime/blob/dcd996daca2573443956c07252c55c2d86dd0320/docs/player-weapon-runtime-mapper.md)、[原生战斗研究脚本](https://github.com/SkyeShade/HD2Runtime/blob/dcd996daca2573443956c07252c55c2d86dd0320/scripts/research_event_combat.py)。本轮核对本地 SDK 数据目录和公开脚本，没有取得新的实机命中样本。

现有 `FIRE` 和点燃绶带是燃烧来源击杀数，继续沿用已接受的来源口径；排除喷火命中不会修改它们。

不能直接用现有燃烧来源白名单排除命中：它也包含燃烧子弹枪械。排除喷火应识别实际的喷射攻击分支；同一武器含普通射击与下挂喷火时，不能把普通弹丸一并排除。

## 近战新接口的候选入口

下列地址是参考构建的研究定位，只用于后续核查，不能直接作为本机当前游戏的可用接口。运行时需验证构建与指令证据。

| 候选入口 | 原生研究已经说明什么 | 仍需证明什么 |
| --- | --- | --- |
| 伤害事件队列 | `DamageEvent` 为 `0x70` 字节；有目标实体、伤害来源类别、造成伤害者、所属玩家、命中部位和伤害量。消费者为 `0x12A7D40`。 | 近战来源类别的实际值及覆盖范围；碰撞和部位伤害是否一对多；零伤害接触是否仍有记录；主机与加入队友时的归属。 |
| 命中缓存 | `RecordHit` 为 `0x62E650`；`missionStats + 0xC040` 有 64 条、每条 16 字节的记录，包含造成伤害者、关联 key 和次数；已有 key 会增长次数。 | key 的真实含义、近战识别、条目复用与重复记录。该缓存不是已证明的按玩家、目标和动作组织的近战计数器。 |
| 近战攻击定义／动作路径 | 专用近战武器的静态组件已可连接到伤害定义；近战动作覆盖存在独立能力配置。 | 枪托、刺刀、链锯是否从同一运行时路径进入事件，以及一次实际接触如何去重。 |

特别保留原研究的两项未知：`DamageEvent +0x20` 是生产者参数形成的命中缓存 key，含义未定；`+0x60` 也没有证明是 `DamageInfoType`。不得把这两个字段直接匹配到近战伤害定义来宣称接通。

本次核对的项目和 SDK 目录没有可用于继续反汇编验证的研究 `.hd2snap`；本轮证据来自源码和生成的静态目录。更深的事件语义、记录生命周期和读取时序需要匹配版本的战斗样本。

## 接口验证与性能边界

验证样本应区分：空挥、命中但未击杀、连续命中同一目标、一次动作涉及多个部位／目标，以及被装甲阻挡。链锯等持续接触的去重口径在取得事件样本后确定，不先用伤害跳动次数代替命中。

优先复用已存在的原生累计读取；若需新接口，只处理本人相关事件并复用已有单位缓存。不得为了绶带增加高频全场单位扫描、屏幕识别或逐次创建 UI 元素。64 条缓存的数据量小不等于其统计语义可靠；低频轮询短暂队列也不能保证不漏记录。实机覆盖与帧数影响均未验证。

## 可观察完成标准

1. 连续快速命中同一类时，屏幕上始终只有一个该类小图标，数量按已验证事件增长。
2. 最后一条有效命中后 2 秒收起小图标；在此之前有新命中则重新计时，累计不会因收起、死亡或切换地图而清空。
3. 地图打开时可在一个累计命中绶带上查看分类数量；新对局清空本场数量。未知类别不伪装成击穿或跳弹。
4. 喷火喷流、持续燃烧和爆炸范围伤害不会新增命中；近战只在接口验证后启用，不用近战击杀数代替命中数。
5. F8 隐藏继续统计；记录和 UI 的开销需与现有性能记录工具对照实测。

逐次穿甲／跳弹分类仍是待接口事项：装甲阻挡与物理反弹可能同时发生，分类及去重不能仅从原生总命中数推断。相关证据继续见 [射击反馈研究](mod-feedback-research-2026-10-11.md)。图标已更新为 v14 待审核，保留6项认可；本轮没有新增实机读取或安装包。此前原型8项、读取器18项离线检查通过，逐次分类与FPS仍待实机验证。

显示适配器须按 v11 图标用途筛选：H02—H09 为即时小图标，H01 仅为累计绶带。原型的 `recent.total` 保留作计数数据，不渲染为即时图标；地图内绶带读取 `cumulative.total`。
