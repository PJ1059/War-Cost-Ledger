# 载具车体来源与碾压规则（0.4.48）

用户确认的本版口径：游戏把本人的击杀记在已确认玩家载具父车体来源下，即计入碾压。该规则使用原有本人 source-stat KILLS 增量，不再要求独立碰撞事件。

## 统一来源表

`docs/vehicle-body-kill-sources.json` 的 `sources` 是完整 16 位大写十六进制资源身份到说明的映射，供计数与界面共同使用。仅纳入 SDK 同时确认玩家 call-in、友军类型、挂载父资源链一致的九个车体：

| 载具 | 父车体完整资源哈希 |
| --- | --- |
| M-102 Gunner FRV | `CC21C7FFD3EBEFB9` |
| M-103 Supply FRV | `9B2140378640432E` |
| M-104 Incinerator FRV | `2D85BFE3D8717FE5` |
| TD-110 Maelstrom | `B0C9FAF4AF8903F9` |
| TD-220 Bastion MK XVI | `16474112801385B6` |
| EXO-45 Patriot | `79E4B3D2DA5E45E3` |
| EXO-49 Emancipator | `C2D449ECF7FACAB1` |
| EXO-51 Lumberer | `7B2326F6FD9C8069` |
| EXO-55 Breakthrough | `35DBF54F016F3624` |

主炮、机枪、机甲武器、炮弹等独立挂载资源不在此表。例如 TD-220 主炮 `1FA1F596769225C2` 与同轴机枪 `439F9E65C18567DA` 均不会作为车体计入碾压。敌方载具、背包无人机、仅有云表名字的未知类型不纳入。自然生成的 Super Earth FRV 与 GATER Oil Rig 没有 SDK 玩家 call-in 定义，本轮保留在排除说明中，暂不扩大适用范围。

`tools/vehicle_body_kill_sources.py` 可从独立 Runtime SDK 重建同一表，并保存四个原始依据文件的 SHA-256。生成器读取实际 `mountChain.vehicleResource`；语义 ID 的末尾不是资源哈希，不能替代。`tests/test_vehicle_body_kill_sources.py` 六项检查覆盖九项重建、挂载排除、非玩家调用／敌方类型／错父资源拒绝。

## 与先前研究的关系

0.4.47 研究中，父车体来源只证明资源归属，不能从旧统计细分每次原生碰撞、车体爆炸或其他父级伤害。0.4.48 按上述用户规则把该父车体来源统一归入碾压；它不会把独立炮／机枪来源或缺失来源总量分配给车体，也不需要改写原生伤害机制。

本机 1403 杀对局 #31 保存了父车体 154、主炮 75、机枪 231 杀三个独立来源。按新口径，154 属于可判定的车体来源；另 522 杀没有保存来源身份，不能归因。对有完整哈希的来源和敌人，0.4.47 名称目录已经覆盖当前保存的全部未知身份；旧字段没有身份的数据仍保留未记录。旧记录如何在界面派生展示与新增量计数是独立接线，不直接修改账户文件。
