# 0.4.60 完整原生表与来源断链修复

固定游戏构建F5FEE03DCFDB的完整表包含1467个原生节点，分别属于ProjectileType（射弹）、ExplosionType（爆炸）、DamageInfoType（伤害）、BeamType（光束）和ArcType（电弧）。各命名空间保持独立，相同数字不互认；同构建二进制和SDK指纹随目录记录。解析新增Beam→伤害/爆炸、Arc→伤害和Explosion→Arc等有实际字段证据的边。

目录保留491个原始资源哈希的typed根，并有182个已命名母来源。运行时可将尚未作为武器命名的原始来源哈希沿这些根解算；单一已命名候选在当前本地伤害或既有首次尸体门槛下作推测归属，多候选继续结合目标1.5秒伤害链或本人附近爆炸。已知真实武器优先。原始哈希、未命名分支和共享候选都保留，使用装备列表不参与指派。

例如未命名载体3B49715551E4CCF1的原生ProjectileWeapon字段为Projectile280，对应GL-21 MK2母来源02EECD0B1FA49630；这个过程通过实际构建入口、隔离Health/entity字节和生涯查询验证，原始一次击杀不变成两次。已有精确哈希名称且具备typed根的来源保持自身身份：鹈鹕40mm与自动炮台虽共享Projectile120，不会只因一个候选已命名就把鹈鹕改成炮台。

原生命中白名单由208扩展为218个有已命名父来源的真实DamageInfo ID。仍用同一个已验证复制入口、ABI1与96字节记录；仅供归属的记录命中计数为0。旧原生profile保留，新profile为native-hit-damage-id-profile-0.4.60.json。完整表含尚无已命名父来源的节点，这些仍保留未知。

同一命中入口进一步冻结真实ProjectileType：通过已证明的原parent frame槽号和ProjectileSystem字段确认同一命中记录，再读取其类型；只在flag2048有效时将记录+32解释为射弹ID，DamageInfo继续使用+36/flag512。旧反射记录的slot不当射弹；元数据校验失败时只省略新ID，保留原命中和伤害编号。反射写回保留已冻结的typed值，命中计数与既有hook位置保持。

爆炸事件公开接口只给名称；257个精确canonical名称或唯一legacy别名可通过同固定Runtime的目录还原其配置ExplosionType，用于核对已有本人爆炸上下文。这是目录名称反查，并非新捕获的逐受害目标爆炸ID。共享射弹、爆炸或破片继续使用实际母来源和时间/位置，保持既有本地击杀门槛。

## 已复现的两处来源丢失

1. 同轮超过8个目标时，已经捕获的DamageInfo原先随临时表清空。保留8目标原生来源增强上限，其余已验证typed联系人利用当前bulk Health和缓存的完整目标身份在Lua处理，不额外读取进程；外层扫描尚未到达的联系人按原0.75秒/最多64条窗口保留。已访问且真实读取失败的记录不靠延迟重放复活。
2. 血量记录消失、仍找到同一目标尸体时，旧代码丢弃已有武器链。现在仅在完整身份匹配、本地来源、最近真实伤害不超过1.5秒且既有原生本人击杀额度成立时继承，并标为推测；过期、换任务/生命、读取间隙或明确队友来源继续清除。

源增强每轮仍最多8个原生目标、512次/32KiB读取、2ms软预算。已验证逻辑重放不是实际FPS测量；无新逐敌永久日志或历史倒填。
