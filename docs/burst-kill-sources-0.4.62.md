# 0.4.62 · 密集击杀来源与空投仓

本轮根据 0.4.61 的最近对局记录排查：原生 1197 杀，敌人明细 1102 杀，已命名来源合计 1017 杀。敌人未知哈希表为空，因此缺失目标主要来自未记录到具体目标；继续补名字不能恢复这些数据。

## 已定位问题

- 普通 Health 来源每轮只深入处理 8 个目标，后续同批死亡可能直接写为未知。现在在同轮复用完整来源实体的核验结果，每个受害目标仍独立验证，保留总读取预算。预算不足的目标短暂等待下一轮，而非立即丢弃来源。
- 原生总击杀与来源分项可能在相邻快照增长。过去忽略仅来源增长，或在来源数大于当轮击杀数时丢弃整批来源；现在在短窗口内匹配两个计数流。
- 已有目标专属来源的目标会消耗无关武器的顺序配额；现在只消耗自身对应配额，让其他有效来源保留给本批其他目标。过期配额先清理。
- 尸体批量到达时，未实际读取的条目也被标为已处理。现在未处理条目短暂排队，首次基线的旧尸体仍不当新击杀。
- 绝地空投仓原本已有精确中文哈希名，但因分类为未知且没有射弹表根而被来源入口排除。独立核验实际投送舱组件后接入初始投放、增援与装备投送三种本体，支架和发射装置不混入。
- 生涯只保存彼此独立的来源和敌人总数，关联明细固定生成一条未知。现在保存实际目标绑定的“敌人哈希→来源哈希→次数”聚合，双向明细按已保存总数封顶，未覆盖部分保留未知；界面标注“推测”。顺序猜配不用于保存这些关联。

## 玩家可见变化

密集击杀时减少被程序提前放弃的来源与目标，空投仓砸死可显示对应舱体来源；仍只显示最后一条击杀，最后目标死亡后 5 秒消失。生涯死因详情移除事件编号，内部去重编号继续保存。

新局中已观察到具体对应关系的武器／敌人可以展开互查。每种“敌人—来源”组合只累计一个数字，不保存逐杀日志；旧局没有关联数据时仍显示未知关联。

## 范围与验证

保留现有奖励条件、账单价格、图案与历史存档。没有目标哈希或来源线索的旧记录不猜填。本版仍使用有界观察和短窗口近似关联，并非完整原生逐杀回调；不同来源同时攻击、对象过快销毁、超过预算或窗口时仍可能未知或误配。

离线复现与回归证据记录在本机 `dist/kill-sources-0.4.62` 和 `dist/burst-attribution-0.4.62`。实际游戏识别率和帧率未验证，不以离线合成案例代替实战数据。
