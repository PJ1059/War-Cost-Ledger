# 0.4.61 玩家死因与附近群体死亡推测

本版独立扩展现有死亡观察器，沿用固定 HD2Runtime 0.30.3 / F5FEE03DCFDB 构建；没有安装、执行或打包参考 DeathSourceNotice 的源码。

## 本次修正

- 原先只处理最终伤害中的燃烧、毒气，现保留射击、跳弹、持续伤害、光束、爆炸、撞击、近战／特殊攻击、其他伤害、溺水、失血；持续伤害再区分燃烧、电击、酸蚀、流血、毒气。未命名元素不臆造名称。
- 每帧只读采样伤害请求队列，缓存同一局、同一本人角色最近 1.5 秒的实际请求。来源 GOID 经实体映射和代际核对后解析完整资源哈希；直接武器、手雷、战备、载具及无歧义的静态弹药父源可以提供伤害来源名称。不会用手持武器替代未识别来源。
- 最终 owned Health 的死亡种类和元素可用时，队列线索必须与其匹配。相同请求不会因为队列滚动或其他请求加入而延长有效期；同一角色后续未知来源不会倒退套用更早已知武器。
- 来源实体消失或来源类型解析失败，不再丢弃已经读到的生命记录及最终死因。自身撞击和溺水不会被旧攻击者标识误归为队友攻击。
- 直接读取仍无机制时，可参考同局、1 秒内、10 米内队友已识别的死亡来源；详情显示“根据附近队友同时死亡推测”。不增加本人死亡数，不传播推测链，不覆盖明确伤害机制、武器或敌人身份。
- 生涯自身死亡按武器／机制分别汇总；详情保存机制、来源哈希以及群体推测距离／时间。旧账户不改写，缺失原始数据的旧死亡不补造。

## 可观察结果

自己的火箭爆炸与坠落／碰撞会显示不同死因。拿到来源资源时，详情还能看到具体火箭、手雷或载具名称；邻近载具事故可作为未知死因的推测补充。没有新的死亡信息时，不会回放旧记录或增加费用、击杀、绶带。

## 读取范围和局限

伤害请求不是原生致死回调，来源配对和群体归因均为推测。撞击枚举不能单独区分摔落、被抛飞和其他碰撞，因此采用“坠落／碰撞”，不宣称所有撞击都是摔死。多人同处一地仍可能受到不同攻击。

每次原生读取保持最多 96 次、4096 字节、2ms 软预算。队列观察前 16 条及滚动 8 条，保留本人最多 4 条请求；大队列、阶段错过、位置缺失、网络来源不可解析时仍可能未知。瞬时队列与原始字节只保留有限内存缓存，不逐条写日志或永久账本。实际游戏识别率、多人准确率与帧率尚未验收。

参考：[用户提供的 DeathSourceNotice 页面](https://www.nexusmods.com/helldivers2/mods/17151)。其部分未知替代为趣味文案，并不代表原始数据完整。只读研究记录保留在本机忽略目录 `dist/death-causes-0.4.61/reference/`；固定 SDK 与自有内存测试用于本项目实现和验证。
