# 0.4.7：整树自动采集已退役

0.4.6完整手动样本成功，已定位16槽任务列表与焦点目标分支。0.4.7不再自动遍历UI树；旧样本和store记录原样保留。本版只自动补读两个缺失的布局函数，在舰上即可完成，见[当前定向诊断](task-layout-code-probe.md)。下文为0.4.4—0.4.6历史探针的预算与验证。

# 自动任务UI定位 · 0.4.6

0.4.5已在六份实机样本中通过控件附着特征校验：HUD全局地址、0x258根偏移和0x144C5C0调用目标都正确。但根节点为kind 0，旧探针错用了普通frame容器的kind 1要求。根的非零flags、无parent／sibling、有效child／context及1920×1080几何字段均被保存；分辨率只作为本次证据，不固定在校验中。

0.4.6使用真实根256字节与8KiB代码窗口作离线回归。公共节点校验接受kind 0；PIN绑定的全HUD入口另外要求kind 0、parent=0、sibling=0，后续仍校验指针范围、父关系和同context。参考来源区分HUD Plus的root_build与widget_init ABI，并与OWHUD的共同base字段交叉核对。新来源 `root_base_v3` 使用 `ui_tree_probe_v3` 存档与 `ledger_ui_tree_v3_*` 文件前缀，不改写v1、v2样本与耗尽次数。完整子树仍未取得。

这是为定位完整任务列表准备的只读测试版。正常游玩时进入战斗、照常打开地图即可；无需选择动作前后样本，也无需保持Codex运行。游戏内 ESC → MODS → 战果与战争账单 → 自动定位任务UI（测试）可关闭，按“应用”立即生效。关闭战果界面不会关闭这项独立设置。

探针复用原有地图状态读取，等待任务显示且ready后才启动。舰上等待没有固定截止时间。地图关闭和打开各最多成功一次、最多尝试3次；文件存在且与当前构建匹配的成功标记会跳过重采。每个10Hz步骤连同原有地图读取共最多16384字节，成功后零额外游戏内存读取。旧手动采集预约或正在运行时优先暂停自动定位。

根节点必须同时通过当前EXE/game.dll构建校验与有界机器码特征验证。读取子节点、兄弟节点、父节点与上下文，最多1024个节点、24层；还保存限定范围的代码窗口，供后续确认任务子树身份。地图、任务、HUD、世界身份变化或读取失败会留下不完整记录。它是分段观察，`atomic=false`，不会证明所有字段来自同一帧。

0.4.6额外限制每步最多16个树节点、32次推进，在推进之间使用2ms软检查点。建档单独一轮，阶段切换后让到下一轮，避免建档／代码读取／节点序列化／最终验证集中在同一回调。同步读取、JSON和文件操作不能在执行中被检查点中断，所以这不是单帧2ms的保证。

0.4.5本局Runtime日志出现账单MOD主回调25.8ms、timer 5为10.2ms。Watchdog同期记录62ms卡顿，其中Runtime约26ms、约31ms未解释；没有阶段计时，不能把25.8ms全部归于探针。该局六份失败样本都是0节点，不能归于完整树遍历。timer序号动态分配，延迟存档写入是候选而未精确证实。截图中的ms/s是区间累计耗时除以真实秒数，不能当作单次耗时或直接算掉帧；顶层HUD+还有未测范围。其他MOD保持。

输出目录为 `%LOCALAPPDATA%/HD2Runtime/mod_data`。每份样本由节点二进制与JSON说明组成；完成状态、失败原因、字节数及根节点验证证据应以JSON为准，出现文件不等于完成。Lua调试摘要入口为 `HD2WarCostLedgerV1.ui_tree_probe_status()`；显式停止入口为 `stop_ui_tree_probe(reason)`。Runtime没有已确认的自动shutdown回调，突然退出时只认定已落盘的完成标记，未完成记录不能用于宣称成功。

本版本不写原生UI位置，也不调用原生移动函数。任务让位仍待确认完整父容器与子树；实际游戏采集、画面布局和FPS尚未验证。此处16KiB是读取上限，不代表没有CPU、文件写入或JSON分配成本。
