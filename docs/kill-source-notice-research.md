# 击杀来源提示的可用证据与边界

核对日期：2026-10-15。只读检查用户提供的 BFV v1.7 安装包及已静态解包 Lua，没有执行、安装或复制参考 MOD 的代码、图案和音频。

## BFV v1.7 的真实做法

对应 `dist/bfv17-research/93E5D0431533CBC9.lua`：

| 位置 | 数据／处理 | 能证明的范围 |
| --- | --- | --- |
| 3176–3180 | 区分死亡事件与 10Hz 来源批次 | 敌人身份／玩家归属和来源计数分别取得，没有逐死者武器字段 |
| 3482–3494 | 死亡对象入 pending_kills，保存 mission、敌名、类型及采样时刻 | 哪个敌人被观察到死亡 |
| 3497–3539 | 保存 player_kill_credited 的 kills、sources、unattributed；只有一个完整正来源时显示其名，多来源显示混合 | 某一统计采样内每种来源增加多少杀 |
| 3452–3477 | 两个队列取头，同 mission 就顺序消费；每消费一个死亡，批次 remaining 减一 | 显示关联由客户端 FIFO 形成，不是原生逐敌配对 |
| 3187、3576–3587 | 缺一侧的项在 0.75 秒后超时 | 不完整内容不会永久等待；先执行匹配再清理，因此不能把这个超时理解成每个既成配对都已验证时间差 |
| 3524–3569 | 仅单个强袭虫无来源死亡，用同帧唯一、完整的 damage 来源恢复名称 | 伤害来源提示的额外推测；仍没有伤害事件与该死者的因果字段 |
| 6343–6395 | 仅本地击杀、排除玩家与设施、实体去重，再进入显示 | 提示过滤与去重，不增加武器到受害者的原生关系 |

“唯一完整来源＋同期只有一个已观察死亡”能支持谨慎的提示推测。来源批次可能包括漏采敌人，敌人队列也可能因轮询、读取与销毁延迟而顺序不同。多个同时发生的来源、持续效果与其他目标上的伤害会进一步造成歧义。当前持枪和一次同帧伤害统计均不能证明该死者的最终武器。

## 本机 Runtime API

固定提交 `dcd996daca2573443956c07252c55c2d86dd0320` 的 `sdk/EventCatalog.json` 与 `runtime/event_sources.lua`：

- `entity_killed` 提供 `entity_id`、`type`（完整资源哈希）、`name/display_name`、`enemy/kind/faction/avatar`、`killer/local_killer/killer_peer`、`observed`，以及可选位置、unit/network/corpse 身份。**没有 weapon/source_type 字段。** 实际派发在 `event_sources.lua` 157–174。
- `player_kill_credited` 提供 `local_player`、`kills`、`total`、`sources` 和 `unattributed`。`sources` 每项为来源完整类型与该来源统计增量，不包含 victim/entity_id。采样与派发在 299–365。
- `player_damage_dealt` 的 sources 是本采样来源伤害总量，没有逐目标 victim；爆炸与状态的后续伤害也可以计在同一来源下。

Ledger 已独立实现 `src/kill-source-attribution.lua`，输出批次、来源数量及未知数，并显式 `per_victim=false`。已有自己的存活→死亡与本人 creditor 观察器，可以用于显示已确认受害者，避免把首次看到尸体的最后攻击归属重新当作新死亡。

## 0.4.49 独立提示实现

按用户反馈，取消 0.4.48 等待完整窗口、显示多条诊断与哈希的方式。当前输出只有 `目标 [来源]`，只有一条一行，始终保留最新一个；界面不附等级、推测标签、哈希或计数。原始身份仍保留在数据字段供排查。

`src/kill-source-notices.lua` 采用独立 FIFO 队列：死亡与本人统计来源一到齐便即时消费；混合来源按各来源击杀额度顺序分配。缺一侧等 0.75 秒；有实际目标但缺来源时，可回退到最近 2.5 秒内有击杀增长的来源，否则显示“未知来源”。不按当前手持武器猜测；只有来源批次却没有目标时不额外制造“未知目标”。这是用户认可的近似显示，不宣称原生逐敌武器关系。

输入保持 `on_death` / `on_batch` / `update` / `snapshot`。目标支持直接死亡及观察器按本人总击杀额度补偿的 `inferred` 尸体事件；设施和他人明确归属排除。`snapshot` 返回缓存 `{revision,items}`，items 长度至多 1，单项 `persistent=true`。临时读断档 `gap()` 丢待配队列但保留最后文本，任务重置清空；F8 随整体隐藏。队列上限 128，近期实体去重 1024；名称按 UTF-8 边界裁至 72 字节，避免溢出。

生产者、备用绘制和原生 HUD 均限制一项一行；原生只创建一个文本控件，保持 1.5 倍字号、排在中央命中与扣费内容下方，绶带仍在右侧。该模块不改写账单、总击杀或历史逐敌武器配对。

专项覆盖即时显示、多来源、近期回退、无目标不造提示、持续保留、替换、任务隔离、临时断读、未知紧凑显示和缓存。完整验证及安装结果记录在本机交付报告；实际任务像素与配对准确率仍待实测。
