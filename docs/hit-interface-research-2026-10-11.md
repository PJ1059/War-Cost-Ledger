# 命中接口接入研究 · 2026-10-11

本轮制作 9 项小图标，并建立离线接入原型。没有将新代码嵌入安装包或加载到游戏；图标审核与接口验证分别记录。

## 九项的接入状态

| 图标 | 项目 | 已找到的入口 | 本轮结论／缺口 |
| --- | --- | --- | --- |
| H01 | 总命中 | `projectiles_hit = 0x897A5551`，来源统计块／`player_hit` | 新增测试证明现有批量读取器可同时读命中、射击和击杀，只读取一次来源缓冲区。仍需在本项目实机核对计数及排除规则。 |
| H02 | 跳弹 | 弹体反弹判断与速度改变路径 | 参考脚本定位到反弹判断；尚无公开逐次反弹事件。不能用“反弹弹体造成的伤害”代替最初跳弹。 |
| H03 | 未击穿／碎弹 | 构造命中信息后的穿甲与目标部位装甲比较 | 必须看到直接接触及被阻挡结果。零伤害不等于未击穿；碎弹是显示名称，不保证游戏模拟了弹体破碎。 |
| H04 | 同级击穿 | 当前弹体 AP 四通道、命中部位装甲 | 有字段和读取路径，缺少实际通道选择及同次接触的关联证据。不能只按武器标称穿甲等级分类。 |
| H05 | 完全击穿 | 与 H04 相同的有效穿甲比较 | 需要使用这次接触的有效穿甲信息；倍率和前次贯穿可能改变它。高穿甲不等于贯穿目标。 |
| H06 | 贯穿 | 接触后的穿甲扣减、速度衰减和继续飞行路径 | 有候选路径，但不能从有伤害／完全击穿推定继续飞行；弹体身份与接触序号需要验证。 |
| H07 | 部位摧毁 | 伤害事件命中 actor、目标分区生命值 | 可研究部位生命值从正数转为毁坏及伤害归属。部位索引、跨部位伤害、移除／复用仍待核对。 |
| H08 | 头部／弱点命中 | 伤害事件 `hit actor` 与敌军部位数据 | 必须建立单位类型与 actor／部位的映射；原生总命中没有头部标记。不是已有爆头击杀接口。 |
| H09 | 近战命中 | `DamageEvent` 生产／消费路径及近战攻击分支 | 静态分支能帮助辨认攻击，不证明运行时接触。未致死、零伤害、枪托、链锯等仍须取样。 |

## 已验证的最小接入原型

`src/hit-feedback.lua` 接受上游已核实的“本人直接接触”记录；它不读取游戏，不推测分类。接口可传数量增长或一条接触，维护固定 9 个数字槽位。

- 同类命中只增长同一数字槽位，不为每次命中分配 UI 节点。
- 最后一次有效命中 2 秒后清空近期反馈；本场累计保留，切换地图或隐藏 HUD 不影响累计。
- 同一次接触可同时有未击穿／跳弹、部位摧毁、弱点命中等信息；总命中只加一次，因此分类数量不能直接相加。
- 未验证、其他玩家、间接伤害、喷火喷流、持续燃烧、地面火焰和范围爆炸均被拒绝；尚无分类的有效命中只增加总数。

`tests/test_hit_feedback.lua` 使用合成接触记录验证显示状态；`tests/test_native_stats.lua` 使用合成原生缓冲区验证已公开命中键与来源归属。测试在游戏安装目录的 LuaJIT DLL 中离线运行，没有读取运行中的游戏。它们证明处理与读取逻辑，不能证明游戏已向我们提供了上述逐次分类。

## 新接口具体定位

核对的公开参考提交为 `dcd996daca2573443956c07252c55c2d86dd0320`，不是当前本机版本的地址保证。本地 SDK 脚本也经过核对；未执行需要 `.hd2snap` 的反汇编脚本，因为现有研究目录缺少快照。

| 结构／路径 | 参考定位 | 应读取／核对的内容 |
| --- | --- | --- |
| 弹体飞行记录 | projectile system + `0x3040`，槽位步长 `0x70` | 速度、位置、生命周期；槽位重用时需辨认新的弹体，不能仅用槽号去重。 |
| 弹体命中参数记录 | projectile system + `0x4D040`，步长 `0xC8` | `+0x0C` 直接伤害定义 ID；`+0x18/1A/1C/1E` AP 四通道；`+0x34` 伤害倍率；`+0x38` 穿甲倍率。它是弹体参数，单独读取不足以证明某次命中结果。 |
| 直接命中处理 | `0x13AC3D0` 取命中参数；`0x13AD4E8` 构造命中伤害信息 | 连接弹体、实际接触和目标部位；必须确认当前参与判定的 AP 通道。 |
| 贯穿后处理 | `0x13AD211..0x13AD24C` AP 扣减；`0x13ADBD3` 速度衰减 | 确认命中判定与继续飞行的关联，不从速度变化单独猜测贯穿。 |
| 跳弹分支 | `0x13B0BF8` 判断入口；`0x13B117D` 使用跳弹后速度参数 | 判定返回值和反弹方向、接触身份尚需实机样本。 |
| 伤害事件队列 | 每条 `0x70`；生产 `0x129DD30`，消费 `0x12A7D40` | 目标实体、`+0x0C` 命中 actor、dealer／owner／creditor、伤害量。低频读取短暂队列可能漏记录。 |

以上三个“命中”结构不能混用：弹体参数的 `+0x0C` 是伤害定义 ID，队列事件的 `+0x0C` 是命中 actor；队列 `+0x20` 和 `+0x60` 含义仍未知。现有 64 条命中缓存也没有提供已验证的目标／动作身份，不直接当作逐次接触事件。

## 异常状态施加计数 · 2026-10-11 补充

用户提出统计敌人被点燃等异常状态的次数。本轮只读核对当前项目与同一参考提交，不启用新读取，不改变已测试的火焰来源击杀绶带。`src/addon.lua` 的 `state.ribbons.ignite` 目前来自火焰来源的 `dealt_kills`，不是点燃人数或状态施加次数。

参考 SDK 的 21 个公开事件中没有状态开始／结束事件。已找到两个相关入口：

- `DamageInfo` 的四个状态槽能说明攻击尝试施加哪些状态；它们是攻击定义，不能证明某个敌人成功进入状态。
- `QueueStatusRequest` 接收状态类型、目标、累积量和施加者；研究定位队列及逐帧消费路径。累积量达到目标阈值才触发状态，再次施加可能只刷新持续时间，因此申请数不能当成功次数。当前目录没有 `.hd2snap`，研究脚本未在本机重新反汇编或实机验证。

| 可研究的玩家异常状态 | SDK 语义标识 | 计数仍缺什么 |
| --- | --- | --- |
| 点燃 | `fire`、`burning_heavy` | 状态首次生效、熄灭、施加玩家；两个燃烧类型若属同一次点燃不能重复计数。 |
| 眩晕 | `stun_small`、`stun_medium`、`stun_large` | 区分累积、免疫、实际眩晕及持续刷新。 |
| 毒气与混乱 | `gas`／`gas_2`、`gas_confusion`／`gas_confusion_2` | 验证两个效果何时各自生效；若展示一个毒气绶带，需要约定同次施加的去重。 |
| 火焰减速／惊慌 | `flamer_slowed`、`fire_panic` | 确认敌人是否实际进入对应状态；SDK 有定义不等于已有可计数事件。 |

建议口径（尚未作为用户确认规格）：以敌方实体完整身份、状态类别及一次有效状态周期去重；未生效→已生效加一，持续伤害和刷新不加，结束后再成功施加可再加。一发范围攻击使八个敌人新进入燃烧时计八次。只有被证实的施加者才归属玩家，不用最后伤害者或火焰武器名字猜。实体消失、复用和读取中断不能当状态结束后重新施加。

状态请求队列每帧消费，单纯 10 Hz 轮询可能漏掉；下一步须核对目标侧有效状态实例及施加者身份，验证申请、阈值、生效、刷新、结束和主机／客机记录。性能路线优先复用已有实体身份与状态变化，研究有界批量读取；没有证据支持“零 FPS 影响”，也不启用全场逐帧扫描。

## 性能与下一步

优先在现有 10 Hz 统计调用中增加已公开的命中键，复用来源缓冲区；上游归属与分类验证通过后才启用对应反馈。新原型本轮未加载，故没有给游戏新增读取或显示开销，也没有实测 FPS 结论。

下一步只验证直接命中路径：普通弹体命中、装甲阻挡、物理跳弹各一组，关联同次接触的本人归属、actor、有效 AP 与分支结果。近战沿用独立候选路径；喷火仍排除。不得用高频全场扫描、屏幕识别或逐帧猜伤害来补分类。
