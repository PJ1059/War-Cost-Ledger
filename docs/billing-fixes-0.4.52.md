# 0.4.52 计费修正证据

## 手雷只在实际脱手后收费

原问题：`Inventory.counts[index*8+0]` 是储备数，拿出手雷时就减少；0.4.51 直接把这个下降当成投掷。

修正：沿用 Runtime 0.30.3 `domains/player_equipment.lua` 的已命名字段 `inventory.slots.held`（record +16）读取手持实体；再通过引擎完整实体代数与实体类型，确认它是当前同款投掷物。总数为储备数加同款在手的一枚。拿出和取消均不减少总数，脱手时才减少。无需固定等待时间、输入按键或爆炸反馈。完整同身体、生命周期、任务、类型及 500ms 连续采样规则保留。

真实 Runtime 内存夹具完成 4 储备→3+在手1→取消4→3+在手1→脱手3 的完整路径：前四步 0 元，最后一步毒气手雷 180 MC，只记一次。身份/资源/库存或手持字段在读取中变化时放弃此读数。无游戏写入和原生调用。旧账目不追溯修改。

## 激光散热片与射击维护分开

工作簿武器页 H 列已含散热片更换价：7 款单兵激光武器每件 75 MC，LAS-98 每件 300 MC。未改变 F 列原射击费率；已接入的激光射击费改名“武器维护折旧费”。持续光束按秒计价的旧未接入部分不冒充发射次数。

复用附送 Overwatch HUD `Source/weapon_heat.lua`、`inventory-profile.json` 已验证研究的 WeaponHeatComponent：manager `game+0x3326D48`，map +40，描述符数组 +64，state 数组 +88，stride 12，state +0 是独立 u32 散热片储备。state +4 热量不是弹药，升温/降温不收费。正式读取前核对同构建 3 段原生 pin，核对本人当前武器实体/同资源/owned 标记，并重复读取储备及数组/描述符身份。普通换散热片的储备下降计件，补给增加不收费，但补给后再次更换继续计费。

`heatsink-reader-evidence.json` 保留来源校验和、布局和完整研究 pin。磁盘 game.dll 为打包加密形态，不能拿盘上 RVA 字节代替运行时指令核对；新读取器在运行时检查研究中的必要指令。离线真实 Runtime 布局夹具首次 43 次、785 B，未超过原有 48 次/4096 B 预算，无原生调用、写入或任何轮询扫描。新版真实游戏换片尚未观察。

## 背包武器全部射出弹药计费

AC-8、GR-8、RL-77 曾因为同一武器具有可编程弹种而整类排除；这使普通弹也不收费。现在所有同来源 SHOTS 增长均按工作簿母武器标准单价计一次母弹（AC-8 120 MC/发、GR-8 3500 MC/发、RL-77 6500 MC/发），不按爆炸子弹药或击杀数加收。补给来源与初始背包来源使用同一消费规则，因此补给后射出的弹药也收费。已有 Spear、WASP、Maxigun、GL-28 等已接入来源保持按各自原价计费。尚未逐次解析高爆/近炸弹模式时统一按母武器标准弹价，不再漏掉全部弹药；可选弹种的额外参考价不叠加收取。

当前工作簿这些可补给背包支援武器的呼叫费用原本就仅含本体及投送、`prepaid_ammo_cents=0`，无需改价或从呼叫费再扣一次。一次性突击兵、EAT、哨戒炮和无人机的整包费用规则没有改动。未修改已保存历史。


## B/FLAM-80 背包燃料

`BackpackAuthoringCapabilities.json` 明确现代 B/FLAM-80（78A8185F63A70795）不拥有弹匣，而通过唯一标签从配套背包（43EB1C3C1A1860E0）Deposit 读取弹药：原生容量500、补给250，计量单位为 ammo，与工作簿“显示单位”一致。旧资源0736BEE2D6328726确有 WeaponMagazine 容量500，继续使用原有fuel库存路径。

现代路径读取本人 owned Inventory 的背包槽，再读取精确同款配套背包 Deposit 的实际余额；不读UI缓存、按键、击杀数，不把SHOTS换算为油料。按原 EQ-113 价格0.3 MC/显示单位收费，初次看到库存、补给增加不收费，之后再次消耗继续收费。必须是相同手持武器、相同背包和相同生命周期，换背包会重建基线。原生稀疏行通过完整实体散列表和描述符定位，不把活跃数量误用为行号上界。

此新路径跨 Inventory 与 Deposit 两个组件，首次需55次读取/682B，独立硬上限64次，原有其他库存路径保持48次，均保留4096B和1ms读取前软预算。离线真实 Runtime 夹具已通过消耗、补给后再次消耗、余额归零、稀疏行、错包、无背包、竞态及pin验证。真实游戏余额与新版账单尚未实测。
