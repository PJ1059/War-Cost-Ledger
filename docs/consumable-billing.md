# 标准治疗针 · 0.4.29

按用户 2026-10-13 的新定价，标准治疗针 EQ-360 为每支 **2500 MC**（内部 250000 分），与主价格表 D190/F190 一致。游戏内选择的货币沿用现有换算；这不是 P-11 治疗剂手枪的针弹价格。

此前准备的 consumable-billing.lua 没有打进正式包，正式 addon 也没请求治疗针使用统计，因此自用治疗针确实漏费。0.4.29 新增专用 stim-billing.lua，复用本人现有 stat_breakdown 结果中的 stims_used（0xC8256789），不增加独立扫描或按回血量猜支数。相同世界、任务、玩家实体和完整 peer 下，使用次数每增加 1 就收 1 支。补给库存增加不收费；没有持枪、生命值不增长、阵亡换身体和 F8 隐藏不影响该计数。

首个有效样本只建立基线，既往消费不追收。缺失或非法读取、玩家身份变化、世界中断、原生计数倒退时重建基线，不把缺口当新增消费。每场合并一条 event=stim_used 明细，state.stims_used 保留本次原生计数，stim_units/stim_cents 保留已收费的支数/金额；进入现有 total_cents、5秒批量保存及结束强制保存。

独立模块和实际构建入口的离线验证见对应 tests/test_stim_billing.lua、tests/test_addon_stims.lua。实机注射后的金额变化需要新版加载后验证；不得用旧版恢复生命值的记录补收费。

# 弹匣废弃与火炬手燃料 · 0.4.10

火炬手 EQ-054 按价格表的每显示单位 0.30 MC 收取燃料消耗。53项已证明使用整匣弹药的装备加入库存计费：每次射击减少的弹药、换弹丢掉的余弹，走同一条费用记录。普通弹药价格和中文名沿用原工作簿，不调整定价。

普通整匣库存为“备弹匣数×当前容量＋弹匣余弹＋已装膛的一发”。容量读取当前武器的私有覆盖或原生类型，可接受其他MOD的弹匣容量。膛内字段是投射物类型标记，不将其数值当成子弹数；火炬手燃料没有额外膛内一发。当前价格表、SDK身份和原生字段证据见 `magazine-pricing-evidence.json`。

只读本人的当前持枪，确认读取前后同一完整实体代际、类型；普通武器还要求原生Weapon flags为整匣模式，排除逐发及热量模式。逐发装填、背包装弹、可切换弹种及未证明的武器保留既有射击计费。首次成功库存读数建立基线，从此本场该价格停用来源SHOTS收费，避免把射出的同一发弹药重复收费。SHOTS与FIRE数字仍按原来的游戏统计展示。

只计连续有效库存的下降。补给增加不收费，空匣装入新弹匣不额外收费；剩20发就换弹，会收取废弃20发的费用。常见工作余弹不同步、备弹先扣和新匣先填的装填中间态暂不收费，最多保留2秒同实例基线。切枪、死亡、世界改变、读取失败或超时断开基线，再读到时不追补缺口。库存数据采样不能完整还原同一间隔内同时补给、开火和丢弃的所有事件；实机字段变化顺序与覆盖尚待验证。

每场每种价格合并一条明细，`event=ammunition_consumed`、`inventory_units`保留库存计费数量，`quantity`为已收费数量，`fuel_units/fuel_cents`保留火炬手燃料。已射出的统计与已收费消费量分别保存；旧的 `m105_billed_shots` 字段沿用为盟友已收费弹药量，现在可含废弃。总额通过现有 `total_cents`进入战争账单，沿用5秒批量保存与任务结束强制保存。首次基线前的消费不补收。

沿用10Hz观察，仅当前持枪，无全场扫描、额外线程、游戏写入或逐发日志。新增读取统一上限48次操作／4096B；每次原生读取前检查1ms软预算，单次系统读取无法被提前中断。离线真实Runtime函数夹具正常火炬手读取39次／402B（类型容量）或37次／378B（私有容量），普通弹匣44次／450B或42次／426B。这些是读取量证据，实际游戏帧率尚未实测。

游戏LuaJIT离线验证纯计费、真实Runtime读法以及实际打包入口。安装前需正常关闭游戏与Arsenal；旧0.4.9包、配置、账目及其他MOD保留。本节为0.4.10当时的弹药实现记录；治疗针接线见上方0.4.29说明。
