# 0.4.0 接入说明

本版接入13项绶带／成就，继续保留28项待接口。沿用用户的价格工作簿、中文译名及敌军定位表，不修改原始成就文档或价格。

## 现在记录什么

`last_mission`保存本场：原生射击／击杀／近战／死亡，观察到的恢复量，绶带／成就，账单明细。新增字段：

|字段|含义|
|---|---|
|unit_kills|按中文名称、英文身份、阵营和用户分类汇总的本人确认击杀|
|class_kills|轻型、中型、中型精英、重型、巨型、BOSS分开计数|
|air_kills|各阵营飞行单位计数；飞行标签可以与重型／巨型重叠|
|asset_kills|已映射运输舰／机器人构造者；非KillScore资产不增加原生总击杀|
|unknown_unit_kills|尚未定位角色的原生类型哈希及观察次数，避免随意套分类|
|weapon_stats|原生来源各自的发射量与击杀量，已知装备／战备附中文名|
|equipment_ammo_cents|全部已识别个人弹药支出；旧ammo_cents仍单指盟友弹药|
|kill_observer|5Hz读取的状态、容量限制、跳过的新描述符数量和耗时诊断|

84个已核对敌军／资产哈希覆盖83行名录中的62种单位，其余21种名字保持待映射。一个型号可以对应多个哈希；一个实例的死亡只记一次。腾讯表的Charger“霸王虫”译名不会覆盖本地“强袭虫”，Hive Lord仍是BOSS。地面光能曲速舰哈希不在当前Runtime生命值目录，已明确留为待接口。

每次死亡只采用当前生命值记录中的归属，不把先前命中过敌人或尸体缓存归属算成最后击杀。没有逐次致死武器字段，因此不拼接火焰累计和巨型累计来颁发“消灭癌症”。5Hz观察可能遗漏短暂死亡；游戏原生总击杀独立保留，分类数字不是完整覆盖保证。

94种常规战备可按原生ID识别。88种按既定调用价格，六种轨道火力网等待实际第一发炮弹后记一次平台费，之后按同一实例的shellsFired增长收费：

|战备|每枚母弹 MC|
|---|---:|
|轨道加特林火力网|30|
|轨道120mm高爆弹火力网|1200|
|轨道380mm高爆弹火力网|6000|
|轨道游走火力网|6000|
|轨道凝固汽油弹火力网|2000|
|轨道空爆攻击|4000|

不按默认齐射次数预收。既有炮击、未关联到自己呼叫的实例、读取前已发生的消费不追补；子弹药和后续爆炸不收费。炮击明细每个实例合并一项。受原有呼叫归属限制，调用及炮击费用目前仅单人主机接入；一旦队友加入，本场此部分暂停，个人弹药与战果继续。

78种弹药、84个来源哈希按游戏原生投射物增长计费，包含解放者、穿甲解放者、机枪、反器材步枪、飞矛、磁轨炮等。霰弹按SDK证明的默认弹丸数折算为壳，余数跨采样保留，防止一壳重复收费。若其他MOD改弹丸数，此换算需实机对照；原生SHOTS保持游戏投射物口径。装备来源统计包含未知来源，但未知或未证明消费单位的来源不计费。一次性武器／哨戒／载具／护卫犬弹药已在包干价中，避免再次收费；近战不按挥动收费，场景既有装备不重新采购，个人盔甲未计费。

以下费用保留明确缺口：丢弃剩余弹匣、连续光束秒数与燃料显示单位、投掷物／治疗剂实际消费、同一来源的可切换弹种及下挂、飞鹰实际返舰重装、增援实际投送、SEAF弹种、鹈鹕真实架次和机炮弹数／人数均摊／基础费。新接入载具调用沿用价格表的平台项；鹈鹕架次基础费及独立分摊仍未接入，不能把本场账单当成全消费覆盖。具体待项随包附在integration-catalogs.json／confirmed-prices.json。

## 性能及验证

没有注册Runtime每帧全场health事件，也没有代码注入、写游戏内存或新增常驻服务。10Hz共用原有玩家统计读取，敌军只读观察每秒最多5次，每次最多64个新描述符，扫描有2ms CPU检查点、4096记录和16384哈希槽上限；超过预算从上次位置继续，避免长帧补扫。生命值数组在1MiB边界分两次读取，避免Runtime单块限制拒绝大表。存储沿用5秒合并和任务结束强制保存。

实际游戏lua51.dll运行构建入口验证：分类／中文／BOSS、多人最后归属、重复／尸体／消失／已死基线／读取断点、99/100轻型、各阵营防空阈值、9/10舰船、资产隔离、保存／重置、不同弹药价格、霰弹折算、包干不重复、不同炮弹总数、600帧只50次敌军观察、长帧不补循环；原六项及HUD/F8回归继续执行。

离线ReadProcessMemory基准读取本测试进程的合成缓冲区，128／1024／4096条存活记录，各2000次。4096条稳定扫描平均约0.33ms，p99约0.51ms；这是读取耗时，不是实战FPS结论。证据见kill-observer-performance.json。没有启动游戏，新增读取的真实覆盖、其他MOD共存及FPS仍待实机验证。现有自动小探针120秒无响应的问题保留，正式战果记录不依赖该探针。

UI设计是下一阶段；本版保留右上角小HUD、原六个短标签与F8开关。新增结果已保存，勋章解锁会记入Runtime日志。
