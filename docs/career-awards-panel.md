# 生涯战果档案与历史对局（2026-10-14）

## 0.4.39 档案区域输入隔离

用户已确认 `docs/career-history-review.html` 的按钮与卡片布局，并追加要求取消删除历史功能。当前实现保留这一布局，数据来自本 MOD 已保存记录；网页示例不会导入游戏账户。

- 面板标题为“战果档案”。累计／历史、全部／24小时／7天／30天具有按钮边框、选中和悬停反馈；对局卡片整个标题区可点击，`+ / -` 表示展开／收起。最近完成的任务返舰后默认展开，包含中途返回舰船的记录。
- 顶部生涯 KD、差值、基准时间与真实检查点趋势相互独立；下方显示场数、击杀、阵亡、时段 KD。趋势最多 24 个真实样本点，缺少可靠基准时不画趋势、不计算差值。“全部”基准为 31 天保留范围内最早已知点，不能宣称为完整生涯起点。
- 对局列表支持鼠标滚轮并显示滚动条，已移除上下按钮。卡片显示本场 KD 和本场对生涯 KD 的影响，展开后显示取得的成就／战果。“查看战果”在面板内打开当前时段图案层，关闭按钮返回列表；打开时不发出底层按钮，避免点击穿透。图案继续提供名称与获取条件。
- 已取消删除按钮、确认流程、输入处理与公开删除 API。现有历史、累计战果、账单、生涯检查点及旧删除标记保留；过去已删除的记录不会重建。容量维持 500 场，满额暂停新增记录、保留已有场更新，不提示删除、不自动清理。
- 固定 32 个文字槽、24 个控件槽、48 个逻辑装饰块与 21 项战果图案，只显示完整位于可见区域内的块。500 场与全部 21 项图案仍可到达；原生父链读取保持 10Hz，输入每帧轻量采样，页面失效取消待处理点击。

时间范围仅接收有可信结束时间的结束或中断记录；缺少日期的旧记录只列入“全部”。区间汇总缺少击杀／阵亡时保持未知，不用已知小计假装总数。最近 24 小时、7 天、30 天的基准为目标时刻之前一小时内最近真实检查点；不存在或过旧均显示缺少基准。只在本次启动已确认真实生涯同步后记录检查点，保留 31 天，每小时首、末两个。

### 显示与点击错位的修订边界

0.4.35 实机文字、图案的显示位置低于对应点击区域；用户点“历史对局”上方后能够打开，证明按钮处理存在。单独改到生涯绘制层 24 没有解决该问题。

0.4.36 保留生涯层 24，为 Career 文字使用独立平面字体参数，为图案使用同名资源的原生菜单材质；原战斗 HUD 的字体和曲面材质不变。该候选依据已保存的原生字体／材质合同，不加经验性 Y 偏移。用户已实机确认 0.4.36 可直接点击按钮与卡片展开／收起，0.4.37 的五层绘制顺序修正后，文字、图案和悬停说明清晰。0.4.38 保留这些已验证部分，改用半透明中性黑灰背景、灰白文字和白色选中边线；移除底部上下按钮，仅保留滚轮浏览提示和滚动条。KD 升降保留语义颜色，战果图案原色不变；0.4.38 配色和滚轮浏览已由用户实机确认。


### 0.4.39 滚轮隔离

原 `hd2.input.wheel()` 仅读取滚轮，不阻止原生列表响应。现在每帧根据已验证的档案区域和鼠标位置调用 Runtime 现有 `hd2.input.block({keyboard=false,mouse=true})`。范围包含累计页、标题、页脚及列表边界；只有历史列表区域消耗滚动距离。鼠标移出、失焦、页面关闭／重建、投影失败或缓存超过 0.25 秒时释放。未申请时不调用全局释放。

拦截同时覆盖区域内的原生鼠标按下和滚轮；档案自身仍通过 Runtime 鼠标状态处理点击，键盘与 ESC 不受拦截。Runtime 使用 0.5 秒续约，脚本意外停止后自动放行。沿用已安装的 Runtime 与其设置，不新增原生接口或修改依赖。离线回归不等于实机输入已验证；需核对区域内仅右侧滚动、移到左侧后正常滚动。

## 0.4.34 点击诊断（旧版研究记录）

0.4.33 已在实机显示栏目，但普通点击和长按 1 秒都不能切换历史；跳弹图案悬停正常。实际部署的 Runtime `input.mouse` 含布尔 left，公开 API 直接透传且后续补丁没有覆盖，已排除依赖版本差异。

离线复现发现一次 `CAREER_PANEL_TIME_BUDGET` 会清空按键状态并把栏目重置为累计，但尚未取得这次实机的同类错误证据。0.4.34 保持原点击行为，只向既有 Runtime 日志写入有限诊断：可见时每秒最多一条常规、总共30条；按下/动作/清空额外最多30条，其中清空最多10条。记录left类型和值、坐标、控件命中、pressed、切换前后栏目和错误原因；不写账户、不增加游戏内存读取。取得实机事件后移除临时诊断并针对实际原因修复。

## 0.4.33 历史对局（旧版记录，非当前操作指南）

在原收藏区增加“累计战果 / 历史对局”切换。历史按任务序号从新到旧，通过上一局/下一局查看日期、状态、击杀、阵亡、KD、该局绶带与成就。图案继续提供悬停名称与条件，项目超出区域可翻页；原战斗 HUD 不变。

正常完成或中途返回舰船，都会由现有任务退出分支保存，不要求成功/胜利信号。断开或退出程序而没有观察到结束时，重启把最后检查点标为“记录中断”，不猜结束时间；最多缺少既有 5 秒批量保存间隔内的数据。序号为 0 的等待状态不会生成对局。

当前 KD 按击杀/阵亡计算；零阵亡显示 `击杀数/0`。只有实际观察到开局且有可靠生涯基准时保存 before，首次结束时固定 after；之后的上舰/页面同步不能改写该场终点。两端完整才显示变化（四位小数），缺项显示 `--`。旧快照没有开始时间与可信生涯端点，不补造这些字段。

旧版曾提供“删除本局／确认删除”两次独立点击，删除只修改 `mission_history_v1`。0.4.36 已取消该入口及公开 API；旧存档的最高已接受序号和必要删除标记继续保留，用于防止重启重建过去已删除的记录。

容量为 500 场。旧版满额时曾显示删除旧局提示；0.4.36 取消该提示及删除功能，维持满额暂停新增、已有场继续更新的存储策略，不自动清理。500 场全部 21 种战果使用 16 位最大安全计数时，实际 Runtime JSON 为 430,070 字节，加旧账户为 451,811 字节，低于 Runtime 1 MiB 限制。旧存档若已有更多场也原样读取。

`src/mission-history.lua` 只处理内存中的已确认 state，观察随既有 persist；revision 改变才复制保存，沿用 5 秒批次与起止立即保存。历史列表只在可见生涯页生成，排序按版本缓存，不新增游戏统计读取、后台服务或逐帧写盘。画面使用已有 HUD+ 父控件和字体。

本机可从核对过 SHA 的旧账户快照恢复任务 16、17、18，其中 17 只有中途样本。恢复工具 `tools/restore-known-mission-history.py` 默认只读，`--apply` 要求游戏和 Arsenal 已关闭，完整备份账户后只新增历史键。重复运行不会重建已经删除的场次，个人快照不随 MOD 分发；更早缺失历史无法重建。

验证：纯记录生命周期、满额/删除/重启、原生模型与鼠标交互、实际 built-addon 提前返舰路径、实际 HUD+ Reader/Widgets 和原战斗 HUD 离线回归通过。0.4.32 累计收藏图案/悬停/字体已由用户实机确认；0.4.33 新按钮、逐局画面尚待实机核对。

在军械库“生涯”页右侧、角色名下方与人物模型之间的空白区域，显示本 MOD 在游戏中取得的成就和绶带。位置依据用户截图 `external/codex-clipboard-a27aba19-93a7-408d-a421-8d76ea173df0.png` 中绿框。

## 累计与悬停合同

`src/career-award-records.lua` 保存 `career_awards_v1`：绶带累计、成就累计、当前任务sequence及单局高水位。只从实际state增加；同任务重复观察、回落、结束重放和重启不重复入账，同局成就boolean最多一次。预览状态不能增加累计。由既有 `persist`/5秒批量保存及任务起止flush负责落盘，不逐帧写文件。

旧数据只迁移一次：明确的最近一局绶带次数，加上已有历史/最近一局成就boolean可证明的至少一次。重合boolean不叠加，不能从总击杀或火焰击杀推算此前未记录的获奖次数。因此新增后显示的是可证明的MOD累计，不是补齐整个游戏生涯的估算。

`src/career-panel-model.lua` 从当前21项图案定义取名称，只显示正数累计，并提供各项实际规则文字。`src/career-panel-feed.lua` 与KD同步开关独立：同一10Hz更新只读父链、累计和光标。鼠标先按Runtime `mod_overlay.lua:604–608` 的既有算法由client像素换算到 `stingray.Gui.resolution()`，再逆原生父矩阵换到收藏区局部坐标。GUI resolution不可用时展示继续，悬停关闭；不猜坐标、不释放或截取游戏光标，不调用滚轮原生hook。
