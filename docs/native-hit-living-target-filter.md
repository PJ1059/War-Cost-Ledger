# 命中目标存活限定（0.4.40）

问题：旧的命中复制钩子只核对目标属于敌人、攻击来自本地玩家的支持武器。敌人死亡后仍可能保留同一种类的实体，因此攻击尸体也可能被记录为命中。

修复在原命中快照的资格检查中，增加 Runtime SDK 已定义的 Health 表查询。只有 `life < 2`、描述符实体编号仍匹配的目标才有资格计入命中；已经死亡、表中没有记录或无法确认的目标不计入。查询最多探测 8 个哈希桶，不扫描所有敌人，不分配内存，不按伤害量过滤，因此活体上的跳弹和未击穿仍能记录。

正常命中在调用原伤害消费者之前冻结存活资格。提交队列时不重新查目标是否还活着，避免漏掉致命一击。反射分支继续使用原有的独立、即时资格检查；失败不会覆盖已经冻结的正常命中。游戏原伤害消费者照常调用，修改只限制 MOD 自己记录的命中。

旧生成器与冻结配置不改动。新配置 `docs/native-hit-living-target-profile-v1.json` 在原拆除诊断配置之上包装 `qualifier`，新增 `health_alive`，把原种类检查保留为 `qualifier_types`。其余入口、原指令回放、提交函数、拆除诊断及跳弹分支字节保持一致。

布局依据：Runtime `domains/event_natives.lua` 的 `health` 和 `runtime/event_world.lua` 的 `health_header/find_index/entity_state`，匹配当前已固定的游戏版本。Health 全局偏移 `0x3326688`；记录步长 440；life 偏移 412；描述符是指针数组，不使用 EntityManager 的内联描述符布局。

验证：

- `tools/native/test_hit_copy_living_target_owned.py`：28 项自有进程回放通过，覆盖存活 0/1、死亡 2/3、未知/退休/复用目标、边界、最多 8 次查询、未击穿、正常伤害消费者照常调用；原消费者内部把目标设为死亡或移除描述符后，致命一击仍提交一次，后续尸体接触不提交。真实反弹网关在对应调用栈内也覆盖活体/尸体，并确认正常致命一击后的反弹资格失败不会覆盖已冻结的正常命中；寄存器、XMM、MXCSR 回放一致。
- `tools/native/test_hit_package.py --profile docs/native-hit-living-target-profile-v1.json`：26 个真实原生函数注册通过；LuaJIT 调用私有队列，66 条记录按 64+2 消费，无重放。
- 以上仅使用测试进程自有内存，没有访问游戏进程、安装临时代码或修改真实账户。尚需安装后在游戏中复核“活体最后一击保留、继续射击尸体不增长”。

局限：无法确认 Health 的目标会保守跳过；超过 8 次哈希探测的碰撞也会跳过。此修复不扩大支持的武器/敌人种类，也不回算旧命中和旧绶带数据。
